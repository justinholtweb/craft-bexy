Totals

Caught here,
not in a
VAT return

Bexy works out what bexio will make the document come to, and compares it with Commerce before the request goes out.

  • A cent-sized gap gets an untaxed rounding position
  • A larger one is refused and explained
Line itemsCHF 499.35
ShippingCHF 12.00
Discount− CHF 25.00
of which MWST 8.1% (included)CHF 36.44
Document totalCHF 486.35

A mis-mapped 7.7% charge is a wrong tax mapping, not rounding. Closing it with a line called “Rounding” would balance the document while it was still wrong, so past roundingLimit Bexy refuses and says why.

Payments

Paid orders
stop sitting
open

Every successful Commerce charge becomes a payment against the bexio invoice.

  • Unique on the transaction, so never posted twice
  • Refunds cancel where bexio permits it
1Order completesA queue job is enqueued — the checkout never waits on bexio
2Document created and issuedSearched for by api_reference first, so it cannot be created twice
3Charge posted as a paymentThe invoice closes in bexio the moment Commerce settles it
4Status pulled backReconcile moves the Commerce order — the status only, never a fake transaction

The connection

A token that
dies quietly
is worse than
no token

bexio expires personal access tokens 60 days after they are created, without telling anybody.

  • OAuth 2.0 with PKCE, refresh tokens stored on every rotation
  • Encrypted with Craft’s security key
Personal access token
60 days

Then it stops, silently. Nothing in Commerce says so; you find out when the quarter does not add up.

OAuth 2.0
Indefinite

Refresh tokens rotate, and Bexy stores the new one every time — which is the step that makes the next refresh work.

Bexy supports both. OAuth is the default for the reason on the left.
